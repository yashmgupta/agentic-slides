# Release checklist

- [ ] Choose a distinct, cleared project name; “SlideForge AI” has existing GitHub/npm uses.
- [ ] Confirm intended owner/repository URL and obtain explicit approval before public creation.
- [ ] Review each research source, license, prompt, screenshot, font, and sample asset for redistribution rights.
- [ ] Replace the illustrative clone URL and update all install links only after repository creation.
- [ ] Run `npm ci` and `npm test` from a clean checkout.
- [ ] Generate all examples; confirm each PPTX opens, contains the expected slide count, native chart data, and notes.
- [ ] Inspect each HTML/PPTX slide in target browsers and Office-compatible applications.
- [ ] Verify all chart values against input and identify synthetic example data as synthetic.
- [ ] Review security boundaries, validation failures, and output paths; confirm no secrets or telemetry.
- [ ] Review the MIT license, dependency licenses, `CHANGELOG.md`, README limitations, and roadmap.
- [ ] Capture fresh screenshots from the actual output with no private information.
- [ ] Complete a real same-brief comparison only if dependencies/licenses permit and record models, versions, costs, and limitations.
- [ ] Draft Medium article without unsupported first-person claims; recheck current Medium policies before publication.
- [ ] Obtain explicit approval before release, paid model usage, or any public posting.
